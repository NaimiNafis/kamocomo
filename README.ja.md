## 問題状況

鴨川は、思い思いに過ごす川です。読書、演奏、ピクニック、犬の散歩。
それぞれのマイペースな時間は、「暗黙知」で守られています。

暗黙知とは、個人の経験や勘、直感に基づき、言葉で簡単に説明できない知識のことです。
鴨川では、たとえば次のようなものです。

- 適度な間隔を保って座る
- 散歩や自転車の通行を妨げない
- 自分で出したゴミは持ち帰る
- 周囲の静かな時間を尊重する

しかしオーバーツーリズムで、従来の使われ方が崩れつつあります。
水着で川に入る、通路を塞ぐように座る、大声で音楽を流す、といった行為が増えています。
注意書きやルールで縛れば解決しそうですが、それは鴨川らしくありません。

チームの問い：**自由なまま、節度をどう伝えるか？**

**現状:** 地域住民と鴨川の間には「用の美」があります。観光客にはまだその関係がなく、
住民と鴨川の関係を破壊しています。**目指す姿:** 住民は自分たちの関係を守り、
観光客も鴨川との間に自分なりの「用の美」を築きます。

## 着眼点

**暗黙知は、教えるものではなく発見するもの。**

- **教える:** ルール・注意書き・看板。鴨川らしい自由が失われます。
- **発見する:** 周囲を観察し、空気を読む。観光客は自分なりに文化に参加します。

## コンセプト：文化を発見する体験を、デザインする

デザインは2つの要素でできています。モノが観光客を呼び込み、Webアプリが
その場所での人の過ごし方を見せます。

### Webアプリ：地域住民と観光客のインタラクションの場

![ストーリーボード。上段は地域住民：川辺の日常が投稿になる。下段は観光客：鴨地蔵を見つけて撮影し、地図上でその日常を見つける。](docs/images/storyboard.jpg)

*上段（地域住民）：川辺の日常が投稿になる。下段（観光客）：鴨地蔵を見つけて撮影し、
地図上でその日常を見つける。*

**地域住民は日常を共有します。** 「親投稿」は、その場所で誰かが何をしているかを記録します。

1. 場所を選択する
2. タグ（読書、音楽などの活動の種類）を選択する
3. ひとことメッセージを追加する
4. 写真を追加する

**観光客は日常を発見します。** 観光客は鴨地蔵のQRコードを読み取り、アプリを開きます。
3Dマップには現在地と川沿いの場所が表示されます。場所ごとに、そこで行われている
色々な行動が見られます。いいなと思った行動には「子投稿」を投稿します。
子投稿は親投稿に紐づく形で残ります。

### 投稿のルール

<p align="center">
  <img src="img/help/main-and-sub-activity.png" width="400" alt="場所のボード：中央に丸い親投稿、周りに四角い子投稿">
</p>

通報ボタンはありません。投票が仕組みを動かします。

- **バッド10個で投稿が非表示になります。** データベースのトリガーが自動で非表示にします。
- **いいねが増えると、子投稿が親投稿の形に近づきます。** 子投稿のカードは四角から始まり、
  いいねのたびに角が丸くなります。いいね10個で、親投稿と同じ円になります。

望ましくない行動は淘汰され、暗黙知が蓄積されていきます。

### カモコレクション

<p align="center">
  <img src="img/help/kamo-collection.png" width="300" alt="カモコレクション：8つの空いたスロットが並ぶスタンプカード">
</p>

鴨川デルタから五条大橋まで、川沿いに8か所の鴨地蔵スポットがあります。
QRコードを読み取るか、その場で写真を撮ると、スポットを集められます。
サーバーは、スポットから120 m以内の場合だけスタンプを付与します。
8か所すべて集めると証明書が表示されます。

- 鴨地蔵にバリエーションを作ることで、**見つける楽しみ**をつくります。
- 自分で撮影した鴨地蔵の写真をコレクションすることで、**集める楽しみ**が生まれます。

## 検証

- **場所:** 鴨川デルタ
- **時刻:** 夕方
- **内容:** 鴨川デルタに鴨地蔵を設置
- **結果:** 通行した3グループ中2グループが写真を撮影

サンプルは少数です。それでも、看板がなくても鴨地蔵が人を引き寄せられる可能性を示しました。

## 用の美

「用の美」は、日常の使用から生まれる美しさを指す考え方です。
チームは、デザインの2つの要素を4つの観点で見直しました。

| | KAMO COMO（Webアプリ） | 鴨地蔵 |
|---|---|---|
| **時間** | 投稿が蓄積し、文化が受け継がれる | その場にあり続け、風景の一部になる |
| **余白** | 観光客が自分なりの体験を重ねられる | 発見・撮影・収集など、関わり方を委ねる |
| **間柄** | 親投稿と子投稿が住民と観光客をつなぐ | 観光客と鴨川の文化をつなぐ |
| **人中心** | ルールではなく、人の行動から文化を伝える | 撮影する行為から自然にWebサイトへ導く |

## 使ってみる

https://kamocomo.vercel.app を開いてください。スマートフォン向けに設計しています。
言語はEN/JAの切り替えボタンで変更できます。

1. 宇宙から鴨川デルタへ飛ぶイントロを見ます。初回は3つの質問に答え、チュートリアルを読みます。
2. 鴨のマーカーをタップします。カメラがその場所へ移動します。**活動を見る**をタップし、その場所のボードを開きます。
3. ボードで子投稿にいいね・バッドをつけます。カードを長押しすると詳細が表示されます。
   **+** で子投稿を、**活動を投稿**で親投稿を追加します。
4. 地図に戻り、**鴨コレクション**を開きます。**テストモード**をオンにすると、現地にいなくても鴨を集められます。
5. **鴨川ログ**を開き、それぞれの場所がこれまでどう使われてきたかを見ます。

## 技術的なポイント

- **ルールはデータベースが守ります。** PostgresのRLS、トリガー、RPCで、1人1票、
  バッド10個での非表示、スタンプの120 m距離チェックを強制します。
  親投稿ごとの子投稿は10件までで、古いものはアーカイブへ移ります。
  クライアント側のチェックは、画面の使いやすさのためだけにあります。
- **アカウント不要。** Supabaseの匿名サインインで、端末ごとにIDを発行します。
  登録なしで使い始められます。
- **3Dマップを月0円で運用。** Google Mapsの `Map3DElement` で鴨川を表示します。
  カメラは鴨川沿いの範囲内に制限しています。1日あたりの上限設定で、読み込み回数をGoogleの無料枠内に収めます。
- **電波が弱くても使えます。** ボード、アーカイブ、コレクションは、最後に取得した結果をIndexedDBに保存します。
  Service Workerがアプリ本体をキャッシュします。オフラインでも、白い画面ではなく保存済みの内容を表示します。
- **リアルタイム・2言語対応。** Supabase Realtimeが、新しい投稿と投票を開いているボードへ届けます。
  d3-forceで投稿を配置します。すべての文言は日本語と英語で用意しています。
